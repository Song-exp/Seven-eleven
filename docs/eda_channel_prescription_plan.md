## 1. 마스터 사전(장부) — 재정의 (원안 수정)

### 1-1. 제품 체급 Mass[p] (동반구매 제거 — leak-free)  ★누수 대응 확정
```
Mass[p] = z(Count sim_kw) + z(Count sim_ip)
```
- **동반구매 Lift 항 제거**: exp47엔 co_offline/co_quick 엣지 자체가 없음(Plan 1). 또한 동반구매는 출시-후 누수라 Mass에 넣으면 Hub_Score 오염 → **sim_kw/sim_ip 구조 차수만 사용**(키워드·IP 공유 기반, 기획시점 가용 = leak-free).
- 2항 각각 z-score(또는 min-max) 표준화 후 합. sim_kw/sim_ip는 edge_index degree.
- ⚠ caveat: sim_kw degree에 약한 "인기 키워드 동네" 밀도 편향(성공 675 vs 실패 336) 존재 — 누수는 아니나, Mass는 hub 가중용으로만 쓰고 성공 예측엔 미사용(원래 용도 유지).

### 1-2. 킬러·지뢰 장부 (순도+지지도로 재정의)
```
Score_succ(k) = Σ_{m∈{1,10,11,12}} Σ_{p∈성공} att_m(p,k)
Score_fail(k) = Σ_{m∈{1,10,11,12}} Σ_{p∈실패} att_m(p,k)
Purity(k)     = Score_succ / (Score_succ + Score_fail)
```
- **Killer**: `성공-우주 지지도 ≥ 3`(성공 제품 3개 이상 연결) **AND** `Purity` 상위 + `Score_succ` 상위 교집합 (예: Purity ≥ 0.7 & Score_succ 상위 15%).
- **Mine**: `실패-우주 지지도 ≥ 3` **AND** `(1−Purity)` 상위 + `Score_fail` 상위.
- raw-sum 단독 top15%(원안)는 보고용 보조 지표로만 — 단독 사용 시 희귀어가 영향력어를 밀어냄.

### 1-3. 허브 장부 (균형 게이트 — 센터 = base rate)  ★Decision 1 확정
```
Hub_Score(k) = Σ_{m∈{1,10,11,12}} Σ_{p∈P(k)} att_m(p,k) × Mass[p]
```
- **확정: `Hub_Score` 상위 10% AND 균형 게이트 `|Purity − base_rate| < ε`** (base_rate=0.238, ε≈0.10~0.15).
- **센터는 0.5가 아니라 base rate(0.238)** — 실측 근거: Purity 분포 전체가 0.2~0.27에 깔림(전역 median 0.206). 어텐션이 성공/실패에 무관하면 Purity → 성공제품 비율(23.8%)로 수렴하므로 중성 기준점이 base rate. (0.5 게이트는 분포 전체를 탈락시킴 = 오류)
- **게이트는 대부분 non-binding이라 저비용**: 고트래픽 상위10% 키워드는 이미 Purity median 0.267·std 0.109로 base rate 수렴 → 87%가 자동 중성. 게이트는 나머지 **12.7%의 "고트래픽인데 성공편향"(soft-killer)만 제거**.
- **부수효과: Hub ⊥ Killer 자동 보장** — Hub(≈base rate)와 Killer(Purity≥0.7)가 게이트로 수학적 배타가 됨 → §1-4 우선순위 규칙 불필요.

### 1-4. 상호배타 규칙 (게이트로 대부분 자동 해결)
- Killer(Purity≥0.7) ∩ Mine(Purity≤낮음)은 정의상 불가. Hub ∩ Killer은 §1-3 균형 게이트로 불가.
- 잔여 경계 중복만 정규화 점수 argmax로 단일 귀속. Cell 4b 비율이 이중계상 안 되도록 단일 귀속 후 집계.

## 2. Stage 0.5 — 혼동행렬 구조 진단 (THR = 0.66)

### Cell 4a — 정량 개요
- **분면 × 채널 교차표** (TP/TN/FP/FN × 세븐/CU/GS25) — 라이브 산출. 도메인 편향 진단.
- 오분류 `pred_success_prob` 히스토그램: 경계선(0.66 근처) 오류 vs 극단(0.05/0.95) 오류 비율.

### Cell 4b — 1-hop 위상 대조 (★ within-channel 필수)
분면별 1-hop 피처 평균표. **피처 축: [제품 Degree | 키워드 Hub도 | 1-hop IP수 | 킬러 비율 | 지뢰 비율]**
```
일반성(Hub도)[Pm] = Σ_{k∈N(Pm)} att(Pm,k)·Hub_Score(k) / Σ_{k∈N(Pm)} att(Pm,k)
```
- **반드시 세븐/CU/GS25 각각(within-channel)으로 산출** + 분면별 채널 구성 병기.
  - 이유(실측): 채널별 평균 Degree 세븐 291 vs CU 172 vs GS25 142 (copurchase가 세븐 전용이라 구조적 격차). FN은 세븐 68.9%로 과대표집 → pooled 비교 시 "성공구조"와 "채널밀도" 신호가 섞임.
- **표의 "높음/낮음"은 가설이지 결과 아님** — 코드가 실측으로 채우고, 가설과 다르면 그대로 보고.

### Cell 4c — 극단 오분류 정성 분석
- FN Top10 / FP Top10: `[제품명 | 실측 매출 | 중분류 | att 내림차순 이웃 키워드 + 장부 태그]`.
- **Ego-Network**: 대표 FP 1 + FN 1, 제품 중심 4대 경로 어텐션 방사형.
  - ⚠ `visualize_network.build_ego`는 **키워드 시드 기반** → 제품중심 ego는 **확장 구현 필요**(드롭인 불가).

### 가설 (검증 대상, 단정 금지)
- FP: [유명 IP + 킬러] 외피는 갖췄으나 본질 개연성 부족 → 모델이 접힘 경로 후광 과신.
- FN: 키워드 빈약 or 지뢰 일부 혼입으로 밀렸으나 실제 성공 → 과거 성공레일 밖 블루오션.

## 3. Stage G-1 — 거시 토폴로지 (성공망 vs 실패망)

- **키워드 투영 행렬** `A_succ`, `A_fail` (2063×2063, scipy sparse 누적):
  제품별 `has_kw`(#1) att 가중 키워드 벡터 `v_p`의 외적 `v_p⊗v_p`를 **우주별 평균**.
- **차분**: `A_diff⁺ = max(0, A_succ − A_fail)`, `A_diff⁻ = max(0, A_fail − A_succ)`.
- **결론 도출**: Rule A(카테고리 앵커) + Rule B(트렌드 속성)의 6:4 매시업을 차분 엣지로 위상 증명. 문맥별 키워드 의미 변절(shift)은 아래 검증3으로.
- **(선택) 허브 위상 검증** — networkx 3.6.1 사용 가능 확인됨:
  1. 엔트로피 대조: 이웃 제품 중분류 분포 `H(k)` — 허브가 killer/지뢰보다 유의(p<0.05) 높은지.
  2. PageRank shift: `A_succ`/`A_fail`에서 허브 PageRank는 불변(뼈대), 국소 응집도만 변절.
  3. **상쇄 검증**: 진짜 허브면 `A_diff⁺/A_diff⁻`에서 독점 엣지 강도 ≈ 0으로 상쇄.
  > ⚠ **순환 주의(Decision 1 연동)**: §1-3에서 균형을 *선택 기준*으로 썼으므로, 위 검증은 "허브가 중성인지 *여부*를 독립 검정"이 아니라 "허브가 *어떻게*(카테고리 분산·구조 백본·상쇄로) 중성인지 **서술**"하는 역할. 중성성 자체의 독립 검정은 §9 순열·hold-out으로 분리.

## 4. Stage G-2 — 미시 채널 분기 (Route A, 핵심)

성공 1,197개를 **1회-forward 결과에서 슬라이싱**:
- **POS-주도 성공** = 성공_소스 ∈ {POS, POS+인스타} → 세븐 932개
- **인스타-주도 성공** = 성공_소스 ∈ {인스타, CU_인스타, GS25_인스타} → 265개

```
A_diff_insta = max(0, A_insta_succ − A_pos_succ)   # 초기 홍보/카피 속성
A_diff_pos   = max(0, A_pos_succ − A_insta_succ)   # 제품 내실/매대 실속 속성
```

> ⚠ **채널 공선 한계 (실측·반드시 명시)**: 인스타-주도 성공 265개 중 **251개(95%)가 CU/GS25**. CU/GS25는 POS가 없어 구조적으로 인스타 성공만 가능 → "인스타 vs POS"는 상당 부분 "타사 vs 세븐".

**2-track, 역할 분리 (★Decision 2 확정):**
- **Track 1 (전 채널, 인스타-주도 265 = CU/GS25 + 세븐 14 포함) — 처방 인스타 어휘의 *주(主) 신호원***
  pooled `A_insta` vs `A_pos`. 265개가 실제 viral-driven이라 가장 풍부한 카피 어휘. 세븐 14개도 진짜 세븐 바이럴이라 **버리지 않고 Track1에 흡수**. 단 "채널차 포함(채널-마커 오염 가능)" 명시.
- **Track 2 (세븐 한정 `POS전용 614` vs `POS+인스타 318`) — *채널 통제 검증자***
  = **"바이럴이 매출 위에 얹혔나(바이럴 부가효과)"**. 세븐 인스타전용 14개는 표본 부족이라 이 대조 셀에선 제외(단 Track1엔 포함). 엄밀히 "인스타 독점"이 아니라 "이미 잘 팔리는 것 중 바이럴까지 된 것의 한계 시그니처" = 인스타-카피의 **채널-통제 하한 버전**(보수적·깨끗).
- **신뢰도 티어링**: `Track1 ∩ Track2` = 고신뢰 카피어 / `Track1 단독` = 저신뢰(채널-마커 의심). get_md_prescription은 Track1로 인스타 버킷 채우되 Track2 교집합으로 신뢰도 플래그.

```
A_diff_insta = max(0, A_insta_succ − A_pos_succ)   # 초기 홍보/카피 속성
A_diff_pos   = max(0, A_pos_succ − A_insta_succ)   # 제품 내실/매대 실속 속성
```

- **결론**: 인스타 독점 키워드쌍(초기 마케팅 카피) vs POS 독점 키워드쌍(제형·내실) 이원 매핑 — Track1 주 신호 + Track2 신뢰도 검증.

## 5. 최종 모듈: `get_md_prescription(seed_keyword)`

`MDPrescriptionEngine` 클래스 = (exp47 1회-forward 캐시) + (장부 3종) + (A_diff 행렬 4종) + (장바구니 보완재 레이어) + (**개입 머신** = Δprob 시뮬레이터)를 dict 결합. 보강 A~F 전부 탑재.

**처방 파이프라인:**
1. **시드 해석**(E §5-6): 그래프에 있으면 그대로, 없으면 임베딩 거리 최근접 대안 + "근거 부족" 가드.
2. **승인 판정**: `seed` 장부 대조 → Killer면 **승인** / Mine이면 **반려** / Hub·미분류면 **중립(주의)**. + **포화/신흥 경고등**(C §5-4).
3. **파트너 발굴**(A §5-2): 메타패스 빔 `keyword→product→keyword`로 1차 후보 → `A_diff_pos`(내실화) / `A_diff_insta`(카피)로 분류.
4. **anti-partner 경고**(B §5-3): 개입 머신으로 Δprob 하락시키는 동반 키워드 = "피하라".
5. **장바구니 보완재**(§5-1): 동반구매 보완 제품·속성 = 번들 제안.
6. **(F §5-7) 실패 컨셉 소생**: 입력이 반려/저점수면 Δprob 극대 보완 키워드 전수조사.
7. 처방 문구 반환(스펙 출력 포맷) + **신뢰도(백테스트 §5-5·검증 §9 통과 등급)**.

> 성격 명시: "승인/반려"는 모델 신호 기반 **권고**지 결정론 아님.

### 공용 — 개입 머신 (B·F·§9 Tier4·5 공유)
`Δprob(p, +k)` = 제품 p의 키워드셋에 k 엣지 추가 후 **재forward**(개입 실험, §0 채널 재추론과 구분) − 원 prob. anti-partner(B)·소생(F)·검증(Tier4/5)이 이 한 머신을 공유.

### 5-1. 장바구니 보완재 순회 레이어 (product→product, 누수 없음)  ★도메인 의도 실현
- **소스**: raw co-purchase 쌍 `data/processed/offline_commerce_edge_lift_pair_out.csv` / `quick_commerce_..._out.csv` (`상품코드_A/B`, `향상도(Lift)`). **모델(exp47)과 독립** — GNN에서 빠진 장바구니 신호를 *직접* 순회.
- **누수 없음 근거**: 시드 제품 자신의 성공을 예측하는 게 아니라, "함께 팔리는 *관계*"를 보는 것 → 시간축 무관(Plan 1 §7).
- **로직**: seed 키워드 → (키워드 보유 제품) → 동반구매 파트너 제품(Lift 상위) → 그 파트너의 키워드/IP = **보완 속성**. *"X와 함께 팔리는 제품들은 {a,b} 속성 → 번들·교차배치 기획"*.
- **출력**: 처방에 "보완재 번들 제안" 필드 추가 (offline/quick 채널 구분).
- (선택) `recommend.py` 순회에 product→product 홉을 옵션 확장하면 키워드-제품-제품-키워드 체인도 가능.

### 5-2. (A) 파트너 엔진 통일 — 메타패스 빔
- **수식**: `score(kt|ks) = Σ_{j: ks,kt∈kw(j)} att(j,ks)·p_success(j)·att(j,kt)` (기존 `recommend.py:recommend_combinations`와 동일 엔진으로 통일 — 검증된 production 함수 재사용, §5-5 백테스트 대상).
- **exp47 기준이라 leak-free**: `p_success(j)`가 동반구매 누수 없는 모델 prob.
- ⚠ **정합 명시**: 빔은 경로 **#1(has_kw) 어텐션만** 사용, 장부 판정은 **4경로**. → 파트너 *생성*=#1 / 승인·분류=4경로 의 **의도된 분업**으로 문서화.
- 발굴된 파트너를 `A_diff_pos`/`A_diff_insta`로 POS-내실 vs insta-카피 분류(§4).

### 5-3. (B) anti-partner — 피해야 할 조합
- **개입 머신**(공용)으로 시드 보유 제품에 후보 파트너 주입 → **Δprob < 0** 이면 anti-partner.
- 추가로 **지뢰(mine) 장부 동반** 키워드도 경고. → 처방에 "이 조합은 피하라" 필드.

### 5-4. (C) 포화 vs 신흥 축 — 블루오션/레드오션 경고등
- **키워드 최초 등장일** = min(보유 제품 `첫_등장일`) ∪ 트렌드 키워드 `인스타_첫_등장일`.
- **누적 상품 수** = 그 키워드 보유 제품 수(지지도).
- 판정: 최근 등장 + 소수 제품 = **🟦 블루오션(선점)** / 오래됨 + 다수 제품 = **🟥 레드오션(포화·자기잠식 위험)**. → 킬러여도 포화면 me-too 경고.
- (FN "블루오션 개척자" 서사 + Rule B 트렌드와 직결)

### 5-5. (D) 백테스트 KPI 격상 — 시스템 메인 스코어보드
- **Precision@K**: hold-out 성공 제품의 *실제 키워드 집합* 을, 그 제품 시드로 처방한 top-K 파트너가 얼마나 적중하나. (= §9 Tier 5.4를 **시스템 헤드라인 지표로 격상**)
- train 장부·train 임베딩으로 추천 → test 성공 제품으로 평가(순환 차단).
- 처방 시스템 전체의 성능 = 이 Precision@K 로 보고.

### 5-6. (E) 시드 입력 견고성
- 그래프 부재 시: ① 정규화(`apply_keyword_normalization` 규칙) 재시도 → ② **키워드 임베딩 거리 최근접** 대안 제시("'X'는 없으나 유사 'Y'로 분석") → ③ 그래도 없으면 "근거 부족" 명시 fallback (현 `recommend.py` KeyError 대체).
- 트렌드 키워드/희귀어(지지도<3)는 "신뢰도 낮음" 플래그.

### 5-7. (F) 역방향 use — 실패 컨셉 인공호흡
- 입력 컨셉(키워드셋)이 반려/저prob → **개입 머신으로 단일 키워드 add 전수조사** → `Δprob` 극대 보완 키워드 top-K 제시 ("이 컨셉에 '마라'를 더하면 +0.12 소생").
- (선택) 2개 동시 add의 시너지(§9 Tier5)까지 확장.

> **A~F 전부 §5 확정 반영.** 공통: B·F·D는 개입 머신/백테스트를 §9 검증 인프라와 공유 → **검증 인프라 = 추천 인프라**.

## 9. 검증 계획 — 도출 키워드·조합의 타당성 (★순환성 차단이 핵심)

### 9-0. 대전제: circularity 차단
장부·A_diff·조합은 모두 **(모델 어텐션 + 성공 라벨)에서 파생** → 같은 라벨로 "킬러가 성공에 붙는다"를 확인하면 **동어반복**. 모든 검증은 아래 4개 독립성 축 중 ≥1개로 순환을 끊어야 인정:
1. **분할 독립** (train→test hold-out)  2. **순열 귀무** (라벨 셔플)  3. **외부 연속지표** (이진 라벨 밖 매출·좋아요)  4. **모델 개입** (엣지 add/remove 후 재forward).
> 구현 전제: 장부를 **(a) full**(처방·서술 production) + **(b) train-only**(hold-out 검증 전용) **2벌**로 빌드.

### 9-1. Tier 1 — 순열 귀무검정 (희귀어 거짓양성 차단) ★필수
- 성공/실패 라벨 **1000회 셔플**(그래프 구조·어텐션 고정, 라벨만 치환) → 키워드별 Purity 귀무분포.
- **판정**: 관측 Purity > 귀무 95퍼센타일 → 진짜 킬러로 인정. 미달은 강등.
- **효과**: 실측상 killer 후보의 **75%가 <10제품 희귀어** → 우연히 성공3개에 붙은 것은 순열에서도 자주 높게 나와 자동 탈락. (이게 §1-2 순도+지지도를 통계로 마무리하는 단계)
- 조합도 동일: 성공/실패 co-occurrence lift의 순열 귀무.

### 9-2. Tier 2 — train→test hold-out 예측 검증 (일반화·순환차단) ★필수
- **train-only 장부**로 키워드 점수: `score(p) = Σ_{k∈kw(p)} signed_purity(k)` (killer +, mine −).
- **test 제품에만** 적용 — test의 어텐션·라벨 미사용, **키워드 집합 membership만** 사용(최대 독립).
- **판정(확정 기준)**: 이 단순 점수의 **test PR-AUC > base(0.238)** 가 bootstrap CI 하한>0.238로 유의. 통과 = "키워드 자체가 unseen 제품에서도 신호". → **이것이 통과/탈락 게이트**.
- 보강(필수 아님): 모델 prob에 점수를 더했을 때 증분은 *참고* 지표로만 보고 — 모델이 이미 키워드를 쓰므로 증분이 작아도 탈락 처리하지 않음.

### 9-3. Tier 3 — 외부 연속지표 (이진 라벨 탈피)
- 이진 `성공여부` 대신 연속 실측: 세븐 POS `daily_velocity`·log`sales_30d_amt`, 인스타 `좋아요 수`.
- **판정**: Spearman(killer-score, log매출) > 0, p<0.05 (세븐 POS). 인스타-카피 키워드는 좋아요수와 양의 상관.
- **의의**: 임계값 컷이 아닌 **전 구간 단조 관계**면 라벨 컷 인공물 아님을 강하게 시사.

### 9-4. Tier 4 — 모델 반사실 개입 (장부 = 모델 실제 민감도인가 = XAI faithfulness) ★필수
- **개입**: 제품 p에 킬러 키워드 엣지 **추가**(또는 지뢰 **제거**) 후 **재forward**(개입 실험 — §0 채널 재추론 금지와 구분됨), `Δprob` 측정.
- **판정**: median Δprob(킬러 add) > 0 **AND** > Δprob(랜덤 키워드 add); Δprob(지뢰 add) < 0. 부호 일치율 ≥ 임계(예 70%).
- **의의**: "라벨 상관"과 독립적으로 "**모델이 실제로 그 키워드에 반응**"하는지 확인. 처방의 XAI 근거 직결.

### 9-5. Tier 5 — 조합(combo) 전용 검증 ★사용자 강조
조합 = `A_diff⁺`에서 성공 공기(共起) 강한 키워드 쌍 (지지도 ≥ N).
1. **시너지(초가법성)**: `Lift_succ(A,B) = P(succ|A,B) / 기대치(A,B 독립)`. 진짜 조합은 marginal 넘는 상호작용(>1). 순열 귀무 대비 유의.
2. **모델 시너지(개입)**: seed 제품에 A, B, A+B 각각 add 후 Δprob → **Δprob(A+B) > Δprob(A)+Δprob(B)** 면 진짜 시너지. 단순 합이면 "조합"이 아니라 독립 2개로 강등.
3. **hold-out**: train에서 찾은 조합 → test 제품 중 그 조합 보유 제품의 성공률 ↑.
4. **추천 백테스트(닫힌 루프)**: 기존 `src/eval/recommend.py:recommend_combinations`(=get_md_prescription 기반)로 seed별 top 파트너 산출 → **held-out 성공제품의 실제 키워드 집합이 추천 파트너로 enriched** 되는지 `precision@k`. (production 함수 그대로 검증)

### 9-6. Tier 6 — 안정성 & 도메인 face validity
- **부트스트랩 안정성**: 제품 부트스트랩/시드 재분할 → top-50 killer Jaccard·Spearman ≥ 0.6 (불안정 = 특정 제품 과적합).
- **알려진 앵커 회수**: 도메인 사전지식(마라·로제·단백질=트렌드 성공형 / 위스키·선물세트=실패형)을 장부가 복원하는지. 못 하면 정의 재검토.
- **MD 정성 평가**: top killer/지뢰/조합 샘플 → 도메인 전문가 타당성·실행가능성 레이팅.

### 9-7. 통과 게이트 요약
| Tier | 지표 | 통과선 | 미달 시 |
|---|---|---|---|
| 1 순열 ★ | Purity vs 귀무 | > 95pct | 킬러/지뢰 강등 |
| 2 hold-out ★ | 키워드점수 test PR-AUC | > base 0.238 (CI 유의) | "신호 없음" 판정 |
| 3 외부 | Spearman(score, 매출/좋아요) | > 0, p<0.05 | 라벨 의존 경고 |
| 4 개입 ★ | Δprob 부호 일치율 | ≥ 70% | 탈락(XAI 충실도 미달) |
| 5 시너지 ★ | 초가법 비율 vs 귀무 | 유의 초과 | "조합" → 독립키워드 |
| 6 안정 | top-50 Jaccard | ≥ 0.6 | 과적합 경고 |

> **승급 규칙**: **Tier 1·2·4·5(★)** 모두 통과한 키워드·조합만 처방에서 "확정", 미통과는 "후보/참고"로만 표기. Tier 3·6은 신뢰도 보강.
> Tier 4를 필수로 둔 이유: 처방의 "승인/반려"는 곧 모델 신호에 대한 행동 권고라, **모델이 실제로 그 키워드에 반응(Δprob 부호)**한다는 보장이 없으면 라벨 상관만으로 처방을 내릴 수 없음.
> **feasibility**: 전부 1회-forward 캐시 + 가벼운 개입 재forward + 기존 masks/`pos_product_features` 매출컬럼으로 가능 (networkx 불요).
