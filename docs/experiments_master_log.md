## 2. 주요 실험 단계별 요약 및 인사이트

### 2.1. 초기 베이스라인 및 하이퍼파라미터 튜닝 (exp01 ~ exp16)
* **주요 목표**: 기본적인 HIN 구조의 뼈대를 잡고, `hidden_dim`(64 vs 128), `pos_weight`(불균형 가중치), `lr`(학습률) 등을 튜닝하는 단계.
* **핵심 발견**:
  * 클래스 불균형 가중치 `pos_weight`를 3.24 정도로 조정하여 학습 손실을 고르게 반영하는 것이 성능 안정화에 기여함.
  * `hidden_dim`을 64로 조정한 설정(`exp16_hidden64` 등)이 128 설정보다 과적합이 덜 발생하고 Test 일반화 성능이 양호함을 확인.

### 2.2. 멀티홉 어텐션 및 키워드/IP 결합 임계 스윕 (exp18 ~ exp31)
* **주요 목표**: 멀티홉 메시지 전파 레이어를 도입하고, 노드 간 연결 밀도를 조정하기 위해 `kw_min_shared`와 `ip_min_shared` 임계값을 실험.
* **핵심 발견**:
  * `exp21_h64_on18` 모델이 0.6867의 Test PR-AUC를 기록하며 강력한 베이스라인으로 자리 잡음.
  * 키워드 공유 임계를 완화(`kw_min` 5 → 3)하면 연결 관계가 촘촘해지지만, 일부 실험에서는 오히려 노이즈가 증가하는 경향을 보여 최적 밀도 조절이 중요함을 확인.

### 2.3. Method B - 신규 간접 엣지 추가 및 격리 격자 실험 (exp32 ~ exp42)
* **주요 목표**: 기존 1홉 메시지 패싱이 해결하지 못하던 간접 경로(`P-I-K`, `P-I-IP-K`, `P-K-K`)를 사전 계산하여 엣지로 연결하고, 최적 조합(엣지 종류 × kw_min × ip_min) 격자 스윕 후 hidden_dim 및 kw 임계 세부 탐색 진행.
* **핵심 발견**:
  * **격자 구조**: 3 엣지 조건(no new / +via+ipip / +all) × 2 kw(5,3) × 2 ip(2,1) = 12셀. +all 행이 kw↓ ip↓ 할수록 단조 증가(0.6659→0.6762→0.6881→0.6959) → 새 엣지는 base 그래프가 촘촘할 때 효과적.
  * **격자 Winner**: **`exp41_trend_kw3_ip1`** (+all new edges, `kw_min=3`, `ip_min=1`, `h=64`) 모델이 **Test PR-AUC 0.6959**를 달성하여 프로젝트 최고 성능을 경신함.
  * **Phase A (hidden_dim)**: 동일 설정에서 h=128(exp35) 시도 → val은 소폭 상승(+0.008)하나 test 하락(-0.012) + val-test gap 0.033→0.053 확대. 과적합 확인 → **h=64 확정**.
  * **Phase B (kw 임계 세부 탐색)**: kw=2(exp42) 시도 → test 0.6959→0.6858로 하락, gap 0.033→0.046으로 기준선(0.040) 초과. kw=1은 sim_kw 엣지 조합론적 폭증으로 GPU OOM → **kw=3이 sweet spot**.
  * **최종 확정 모델**: `exp41_trend_kw3_ip1` — +all, kw=3, ip=1, h=64, test PR-AUC=**0.6959**, val-test gap=0.033.

### 2.4. α_r 분화 개선 시도 및 공동구매 엣지 기여도 분석 (exp44 ~ exp47)
* **주요 목표**: DiffMG 게이트가 키워드 4개 경로(has_kw / via_ip / ipip / trend)에서 α_r≈1/24로 균등 수렴한 원인을 해소하여 관계 중요도 해석력을 높이는 방법 탐색.
* **실험 구성**:
  * **exp44** (`use_lift_weights: true`): Lift 수치를 edge_attr로 활성화 → co_offline α 0.131→0.161로 오히려 증가, test 0.6959→0.6741 하락. 키워드 α_r std=0.0 변화 없음.
  * **exp45** (`lr_alpha: 0.05`, `temperature: 0.2`): 게이트 학습 강화 → co_offline α 0.897로 폭주, test 0.6610 (최악 일반화). 키워드 α_r std=0.0 변화 없음.
  * **exp46** (exp44+exp45 동시): test 0.6375 (전체 최저). 두 효과 충돌.
  * **exp47** (`co_offline·co_quick 제거`): test 0.5699 (exp41 대비 **−0.126**), val-test gap 0.008로 수렴. 키워드 α_r std=0.0 **여전히 변화 없음**.
* **핵심 발견**:
  * co_offline + co_quick 2개 관계가 예측력의 핵심 — 제거 시 PR-AUC 0.126 급락.
  * 키워드 경로 균등 수렴의 원인은 co_offline 지배가 아니라 **랜덤 키워드 임베딩** — 4경로가 구조적으로 구분 불가능하여 어떤 개입으로도 분화 불가.
  * α_r 분화를 위해서는 키워드 임베딩 초기화 방식(random → content-based)을 변경해야 함 (현재 범위 밖).
* **결론**: 4가지 실험 모두 exp41 대비 성능 또는 일반화 기준 미달 → ~~exp41 최종 확정 유지~~ **(§2.5에서 번복: 동반구매 누수 판명)**.

### 2.5. 동반구매 누수 판명 및 최종 모델 exp47 전환 (2026-06-21)
* **계기**: MD 처방 EDA 착수 중 동반구매 엣지의 시간축 타당성 점검 → **target leakage** 발견.
* **누수 진단 (실측)**:
  * 동반구매 엣지 **성공 제품 보유율 46.1% vs 실패 5.4%** (실패는 적게 팔려 동반구매 쌍 형성 불가 = 구조적 부재).
  * **동반구매 degree 단독으로 성공예측 PR-AUC 0.518** (base 0.238의 2.2배) — 모델 없이도 예측. 성공 평균 degree 2.4 vs 실패 0.1.
  * lift CSV에 날짜 컬럼 없음 + 등장 제품 전부 NPD → 출시-후 행동 불가피. 신제품은 출시 *전* 동반구매가 정의상 0 → **시간축 필터 불가, 제거가 정답**.
* **§2.4 재해석**: exp47의 −0.126 하락은 "co_offline이 예측력의 핵심"이 아니라 **"누수 신호 제거분"**. cold-start(출시 전 추천)에선 어차피 못 쓰는 정보.
* **운영점 동등성**: 생존율 23.8% 동기화 임계값에서 exp41(THR 0.6647) P=R=F1=0.668 vs **exp47(THR 0.7755) 0.666** — 실질 손실 ≈0. PR-AUC 차이는 랭킹 꼬리(누수)뿐.
* **exp47 leak-free 검증**: 잔존 상위 관계 sim_kw(보유율 98%v94%)·has_kw(100%v100%)는 구조적 부재 없음 = 내용 유사성(기획시점 가용) = 의도된 cold-start 메커니즘. 잔여: sim_kw degree 약한 밀도 편향(누수 아님), train-val gap 0.215(과적합).
* **결론**: **`exp47_no_copurchase`를 최종 채택**. THR=0.7755. 장바구니는 분류기 입력에서 빼고 **별도 product→product 보완재 인사이트 레이어**(처방 §5-1)로 재배치.
* **후속 → Model v2 (구현·풀학습 완료)**: 장바구니를 *누수 없이* 학습 복원.
  * 접근 2(멀티태스크 동반구매 link-pred, train쌍만) + 접근 3(키워드 보완 엣지 8,846) + §9-6 정규화. 코드: `experiments/v2_multitask.py`·`src/models/hin_gnn_v2.py`·`src/data_builder/build_basket_comp_edges.py`.
  * **결과: test PR-AUC 0.6003 / val 0.6041 / gap 0.190** — **exp47(0.570) 초과 (+0.030)**. 누수 없이 cold-start 성능 향상 확인.
  * **§9-3 누수 재검증 통과 ✅**: aux 양성쌍 100% train + **train-only basket 재학습 test 0.5921 (full 0.6003과 Δ0.008)** → basket_comp test-의존 엣지(41%) 빼도 성능 불변 = 누수 영향 미미.
  * **§9-6 정규화 스윕**: sweepA(dropout0.5/dropedge0.35/hidden32/aux_λ1.0) → **test PR-AUC 0.6081 / gap 0.147** (best). sweepB(+wd0.004/de0.4) gap 0.135/test 0.599. gap<0.10 미달이나 exp47 대비 test +0.038·gap 개선.
  * **승격 판정 = ✅ 권장 (1차 보류는 지표 오류, 정정 후 뒤집힘)**:
    - 1차 보류는 **full-set 운영점 F1**(v2 0.635<exp47 0.666) 기준이었으나, full-set은 train 과적합으로 부풀려진 값(exp47이 더 과적합) → exp47 편향.
    - **정정(test-only 공정 비교)**: **운영점 F1 exp47 0.544 vs v2 0.583(+0.039)** / test PR-AUC 0.570 vs 0.606(+0.036) / gap 0.215 vs 0.135. → **v2가 held-out 두 지표 모두 승 + leak-free.**
    - **결론: v2-sweepA 승격 권장.** 단 (i) test셋 작아 운영 F1 차는 노이즈 가능, (ii) 서빙 교체엔 HINGNNv2+basket_comp 어댑터 필요. 현 서빙은 exp47(어댑터 구현 전까지).
    - 교훈: 운영점은 반드시 **test-only**로 비교(full-set은 과적합 모델 유리).

### 2.6. sim_kw IDF 정규화 시도 (C안) — ★negative result, 폐기 (2026-06-22)

> 배경: network_eda — 어텐션 α_r의 **61%가 `sim_kw`에 집중**인데 sim_kw 단독 변별 PR-AUC 0.332(평탄)·이웃 deg 208·**일반어로만 만든 엣지 66%**. 반면 `sim_ip`(α 0.10)는 단독 PR-AUC **0.617≈전체모델**. → "노이즈 sim_kw가 어텐션을 낭비한다" 가설. 상세 진단: `docs/sim_edge_influence_eda_plan.md`, `docs/findings/2026-06-22_sim엣지-퇴화-sim_ip가신호.md`.

* **C안**: sim_kw를 **키워드 IDF 가중 공유합**(`S=A·diag(idf)·Aᵀ≥τ`, τ=12)으로 재구축 → deg 208→12, 일반어비율 66%→4%(노이즈 96% 제거). 학습 레시피는 sweepA와 동일(그래프 변경 순효과만). 코드: `build_hetero_data._hop2(hop2_kw_idf)` + `experiments/train_sim_idf.py` → `experiments/results/v2_sim_idf`.
* **결과: test PR-AUC 0.593 (A 0.608 대비 −0.015) / train-val gap 0.204 (A 0.115 대비 +0.089)** — **두 지표 모두 악화.**
* **진단(왜)**: α_r는 의도대로 재분배됨 (sim_kw 0.61→**0.43**↓, sim_ip 0.10→**0.33**↑). 그런데도 test↓ gap↑. → **퇴화 sim_kw는 "변별자"가 아니라 "정규화기"였다.** 빽빽한 generic 연결(deg 208)이 메시지패싱에서 임베딩을 평균으로 끌어 **암묵적 스무딩=과적합 억제** 역할. 솎으니(deg 12) 스무딩 소멸 → train 과적합(train_pr 0.818). sim_ip로 옮겨갔지만 sim_ip는 희소(보유율 0.20)라 80% 제품의 잃은 스무딩을 못 메움. 전이ablation drop은 여전히 미미(A 0.0005 / C 0.0027 = 누수 아님 재확인).
* **결론**: **C 폐기, A(v2_sweepA) 유지.** 비변별적이라도 **밀도 자체가 GNN 정규화**라 단순 제거(threshold)는 해롭다. 올바른 방향 = **IDF를 edge_attr로** 붙여 밀도(정규화)는 보존하고 집계 시 generic 기여만 다운웨이트 (다음 실험 후보). 단일 run 변동성 있으나 gap +0.089는 실제 효과.
* **인과 표현 정밀화**: 증명한 건 "sim_kw가 **기능적으로** 정규화 역할(떼니 gap↑)"이지, DiffMG가 *그 목적으로* α 0.61을 줬다는 동기는 아님(최밀집 관계라 질량을 많이 먹은 것일 수도). 안전한 진술 = "sim_kw 몰림은 누수도 아니고 정규화로 일하므로 제거는 손해."
* **처방 해석 메모**: MD가 α_r을 "성공 동인"으로 읽을 때 **sim_kw 0.61을 '키워드 유사성이 동인'으로 오해 금지** — 구조적 스무딩일 뿐, 실제 변별 신호는 **sim_ip**. (findings: `2026-06-22_sim엣지-퇴화-sim_ip가신호.md`)
