# sim 엣지 — sim_kw는 퇴화 노이즈, sim_ip가 진짜 신호 (누수는 아님)

- 모델: **v2_sweepA** | 날짜: 2026-06-22 | 태그: 구조/아키텍처 발견
- 도구: `src/eval/md/sim_diag.py` (S1~S4) · 노트북 `eda/sim_edge_influence/sim_edge_influence.ipynb`
- 배경: network_eda 리포트 M0 — 어텐션 α_r의 **87%가 sim_kw(0.61)·sim_ip(0.21)에 집중** → 누수 의심에서 출발

**S4 — include_sim 처방 토글**
- killer 후보 margin은 +sim에서 일제히 증폭(평균 Δ≈+0.015)되나 **순위 rank_flip 전부 0**

## 해석

1. **누수 아님 (확정).** sim_kw/sim_ip는 공유 키워드/IP로만 구축(`_hop2`) = 출시 전 정보. S3에서 train↔test 교차엣지를 끊어도 PR-AUC가 0.0005만 빠짐 → 모델이 "train 이웃 라벨 조회"로 점수를 떠받치지 않음. 전이적 낙관도 미미.
2. **sim_kw는 퇴화한 prior 채널.** 공유≥3이 너무 낮아(일반어 간식이 2476개 제품에 등장) 준-완전그래프가 됨(deg 208, 66% 일반어 결합). 어텐션 0.61을 먹지만 4분면 성공률이 평탄(0.42~0.30)하고 단독 PR-AUC 0.332 → **변별 거의 없는 평활/prior**.
3. **sim_ip가 진짜 변별자.** 단독 이웃성공률 PR-AUC **0.617 ≈ 전체 모델 0.608**. 즉 모델 성능의 대부분은 "성공한 유사 IP 제품과 닮았나"에서 나옴. IP 공유는 희소·구체적이라 신호가 또렷.
4. sim 켜도(include_sim) 처방 순위 불변 → 모드 전환 안전. cold-start 시뮬을 배포 현실에 맞추는 용도로만 의미.

## 확정 함의

- **누수 의심 종결.** sim 집중은 homophily(유효·배포가능), 전이적 누수 아님.
- **개선 방향 = 깊이(L=3) 아님, 정규화.** 키워드 IDF 가중(`S=A·diag(idf)·Aᵀ≥τ`)으로 sim_kw 재구축. **재학습 전 미리보기**(`sim_diag.idf_sim_sweep`): τ≈12에서 deg 208→12, generic_only 0.66→0.04, 노이즈 96% 제거. 단 변별력은 0.33→0.39로 소폭(sim_ip 0.62엔 못 미침).

## ★ 후속 검증 — C안(IDF τ12) 재학습 = negative result (2026-06-22)

**가설 반증.** IDF로 sim_kw를 솎아 재학습한 결과(`experiments/results/v2_sim_idf`):

| | A (현행) | C (IDF τ12) |
|---|---|---|
| α_r sim_kw / sim_ip | 0.61 / 0.10 | **0.43 / 0.33** (재분배 ✅) |
| test PR-AUC | **0.608** | 0.593 ⬇ |
| train-val gap | **0.115** | 0.204 ⬆ |

- α_r는 의도대로 sim_ip로 옮겨갔으나 **test↓ gap↑ (둘 다 악화).**
- **이유: 퇴화 sim_kw는 변별자가 아니라 정규화기였다.** 빽빽한 generic 연결(deg 208)이 임베딩 스무딩=과적합 억제. 솎으니 스무딩 소멸 → train 과적합. sim_ip는 희소(보유율 0.20)라 80% 제품의 잃은 스무딩을 못 메움.
- **결론: C 폐기, A 유지.** 비변별적이라도 **밀도=GNN 정규화**라 threshold 제거는 해롭다. 올바른 방향 = **IDF를 edge_attr로** 붙여 밀도 보존 + 집계 시 generic만 다운웨이트 (다음 후보). 실험 대장 §2.6.
- **L=3 재귀(B안)는 homophily·오버스무딩을 키울 뿐** — 대조군으로만 둠.
- 처방/combo 기본 모드: 순위 불변이므로 당장은 direct 유지, S5 정규화 후 배포현실(+sim) 재검토.

## ★ 라운드 종결 결론 — A 유지 (2026-06-22)

이 라운드는 **"누수 의심 → 누수 아님 + 어텐션 몰림도 정상"** 으로 닫힘. 최종 정리:

1. **누수 아님 (3중 확인).** ① 구축이 출시 전 정보(공유 키워드·IP) ② 전이 ablation drop 0.0005 ③ 떼어내도 숨은 누수가 드러나는 게 아니라 *정규화를 잃어* 악화.
2. **어텐션 몰림 = 적신호 아님.** sim_kw 0.61은 변별이 아니라 **정규화(스무딩)** 로 일하며, 떼면 과적합으로 손해 → 떼면 안 됨. **A(v2_sweepA) 유지.**
3. **진짜 변별자는 sim_ip** (단독 PR-AUC 0.617 ≈ 전체 0.608).

### 인과 표현 정밀화 (over-claim 방지)
- 증명한 것: sim_kw는 **기능적으로 정규화 역할** (떼니 gap 0.115→0.204). ✅
- 증명 안 한 것: DiffMG가 *그 목적으로* 0.61을 부여했다는 동기. sim_kw가 최밀집 관계라 어텐션 질량을 많이 먹은 것일 수도 → "왜 거기 몰렸나"의 동기까진 **단정하지 않음**.
- 안전한 진술: *"sim_kw 몰림은 문제 없다 — 누수도 아니고, 그 밀집 관계가 정규화로 일하므로 제거는 손해다."*

### 처방 시스템 해석 메모 (★ MD가 α_r 읽을 때)
**`sim_kw` α 0.61을 '키워드 유사성이 성공 동인'으로 오해 금지.** 그건 구조적 스무딩이고, 실제 성공 변별 신호는 **sim_ip**. 모델 타당성과 무관하나 α_r을 "무엇이 성공을 이끄나"로 해석할 때 반드시 구분.
