## 1. NPD 정의 — 3단계 필터

```
[1단계] 파레토 필터 (중분류 기준)
  B4_ITEM_DV_INFO_with_survival.csv
    → 대분류 22개 (식품 관련)
    → 중분류 파레토 포함(O) 46개
    → B4_ITEM_DV_INFO_filtered.parquet (49,362개)

[2단계] burn-in 필터 (개별 상품 기준)
  데이터셋 최초 영업일(2025-01-01) + 14일 = burn-in cutoff 2025-01-15
  is_npd = True   → 첫판매일 >= 2025-01-15  (2025-01-15 당일 포함 이후 등장 = 신규)
  is_npd = False  → 첫판매일 <  2025-01-15  (기존 상품)

[3단계] 음수 순매출 제거 (개별 상품 기준)
  출시 30일 내 순매출(sales_30d_amt) <= 0인 제품 제거 -> 첫 등장시점 후 한 달 동안 환불이 더 많다는건 그 이전에 등장헀었다는 말.
  사유: 반품이 판매를 초과하거나 취소 전용 거래만 존재 (데이터 품질 이슈)
  → B4_filtered is_npd도 False로 동기화
  → 01 Phase 1D에서 pos_product_features.parquet 저장 직전 적용

→ 최종 NPD: pos_product_features.parquet (3,006개, 2025-01-15 ~ 2025-12-31)
  ※ 기존 2,411개 + 2026-06-01 확장 595개 = 3,006개 확정
  ※ 기존: 2,533개(burn-in 필터) - 122개(음수 매출) = 2,411개
  ※ 확장: 5개 중분류 643개(burn-in 필터) - 48개(음수 매출) = 595개 추가
```

> **주의**: 파레토 포함 카테고리라도 2025-01-15 이전(`<`)에 이미 팔리던 제품은 `is_npd=False` (기존 상품).  
> 2025-01-15 당일 첫판매 제품은 NPD로 포함됨 (가공우유 디저트39 3종 등).  
> 순매출 ≤ 0 제품은 반품/취소로 간주하여 NPD에서 제외 (122개: 글렌피딕 40년·선물세트류·행사상품 등).

|---|---|---|

## 5. 성공/실패 라벨 정의

> 구현 위치: `01b_matching_diagnostics.ipynb` (`pos-success-final-summary`, `insta-success-1500` 셀)  
> 최종 출력: `data/processed/npd_success_labels.csv`

---

### 5-1. POS 성공 라벨 (`pos_success`)

**기준**: 중분류 내 파레토 80% — 30일 매출 기준 내림차순 정렬 후 누적 매출 80% 이내 제품 = 성공(1), 이외 = 실패(0)

- 간식빵은 **캐릭터빵 / 나머지간식빵**으로 분리 후 각각 파레토 적용 (Case B 확정)
- `sales_30d_amt` 없는 제품(30일 내 판매 기록 없음): `pos_success = NaN`
- 대상: `pos_product_features.parquet` 전체 3,006개 (2026-06-01 기준)

```
성공(1) + 실패(0) + NaN = 3,006개
```

---

### 5-2. 인스타 성공 라벨 (`insta_success`)

**기준**: 제품별 세븐일레븐 인스타 게시물 좋아요 수 합산(`좋아요합`) >= 임계값, 인스타 제품을 포함시켰을 때 POS만으로 구성한 제품의 성공:전체 비율(35%)를 유지하는 임계값으로 결정

- **현행 임계값**: 3,000 (`INSTA_THRESHOLD = 3000`, `insta-success-1500` 셀에서 조정 가능)
- **분석 대상**: 브릿지(`seven_eleven_product_master`) 경유 ITEM_CD 매핑 가능한 전체 제품 — **NPD 여부 무관** (인스타 등장 전체)
  - 변경 이력: 기존 B4 `is_npd=True` 필터 → 제거 (2026-05-31, `38c84f2d` 셀)
  - `is_npd` 컬럼은 분석용으로 유지 (B4 기준 NPD 여부 확인 가능)
- 인스타 미등장 제품(브릿지 매핑 불가): `insta_success = NaN`

---

### 5-3. 합집합 성공여부 (`npd_success_labels.csv`)

**정의**: POS 성공(1) OR 인스타 성공(1) 중 하나라도 해당하면 `성공`, 아니면 `실패`

| 케이스 | pos_success | insta_success | 성공여부 |
|---|:---:|:---:|:---:|
| POS+인스타 모두 성공 | 1 | 1 | 성공 |
| POS만 성공 | 1 | 0/NaN | 성공 |
| 인스타만 성공 | 0/NaN | 1 | 성공 |
| 모두 실패/미등장 | 0/NaN | 0/NaN | 실패 |

**대상 범위**: `_df_final`(POS NPD 3,006개) ∪ `_combined`(인스타 브릿지 매핑 전체) ITEM_CD 합집합  
**소스 조회**: `pos_b4_insta_pool.csv` 기반으로 상품명·중분류·소분류 매핑
