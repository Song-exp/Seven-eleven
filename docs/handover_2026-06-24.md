## 1. 이번 세션 완료 작업

### A. 조합망 AI요약 개편 — "손해" 프레이밍 제거 ✅
- **문제 진단**: 로제 요약에서 💚좋아지는=쫄깃함인데 🚫손해=떡·면(둘 다 쫄깃)이라 **모순처럼 보임**. 원인은 substitution — 이미 쫄깃함이 레일에 깔려 떡·면이 **중복(대체재)**이고, 실측 margin도 −0.3~0.8%p ≈ 거의 0인데 "손해"로 과장됨. (bypass margin은 hop1≈0 → 쫄깃함 채택 후 hop3·4에서야 음수로 떨어짐 = substitution 증거)
- **조치** (`dashboard.html` `renderComboExplain`): 🚫손해 줄 **삭제**. 노드를 누르면 시너지가 드러나므로 요약은 긍정 추천만.
- **추가**: 🧡 **잘 어울리는 IP(콜라보 후보)** — `type:'ip'` 엣지를 어텐션 가중(=선 굵기) 내림차순 상위 4개. 그래프의 "선 굵을수록 강함"과 일관.
- **정정**: 첫 문장 "가장 자주 함께 쓴 속성"(빈도, 사실과 다름) → "성공 확률을 가장 크게 끌어올리는 순서"(실제 Δprob 인과 리프트 순서).

### C. ★ LLM 프로바이더 스위치 (로컬 Ollama ↔ DeepSeek API) ✅
- **로컬 Gemma는 코드 그대로 보존**(`_ollama` 무변경). DeepSeek를 형제로 추가:
  - `_deepseek` (OpenAI 호환 `/chat/completions`, `deepseek-chat`)
  - `_llm` 디스패처 — `LLM_PROVIDER` env로 라우팅. 반환 계약 동일(실패=빈 문자열→템플릿 fallback)
  - `llm_warmup` — Ollama만 콜드로드(DeepSeek면 no-op). `api.py` warmup 교체.
- **프롬프트 그대로** — DeepSeek엔 기존 `_P_EXPAND`/`_P_SELECT`/`_P_NAME_BATCH`/`_P_DIAG`를 **단일 user 메시지**로 전달.
- 기능 호출 3곳(속성·네이밍·진단) → `_llm` 경유. `/combo`·`/network`(GNN)은 LLM 미사용이라 무관.
- **키 관리**: 코드 하드코딩 X. 의존성 없는 `_load_local_env()`가 프로젝트 `.env`(gitignore됨) 적재. `.env`에 `LLM_PROVIDER=deepseek` + `DEEPSEEK_API_KEY` 설정(현재 deepseek 활성).
- **스위치**: `.env`의 `LLM_PROVIDER` 한 줄 — `deepseek`(배포·무GPU) ↔ `ollama`(로컬 Gemma).

### D. ★ 어휘 제약(vocab-constrained) 키워드 매칭 ✅
- **문제**: 기존 `_match_to_graph`(substring)는 100% 그래프 멤버는 보장하나 **오매칭/누락** 발생 — `스파이시→파이`(spicy→pie), `부드러운→(드롭, 부드러움 있는데도)`. 문자열 통계만으론 `로제소스→로제`(정상)와 `스파이시→파이`(오류) 구분 불가 = 의미 필요.
- **해법** (`serve.py`): 그래프 키워드 1,923개를 **허용 어휘 목록**으로 LLM에 주고 그 안에서만 고르게 + **exact 멤버십 후필터**.
  - `_P_SELECT`(어휘 제약 프롬프트) · `_graph_vocab_str()`(어휘 1회 캐시) · `vocab_select()`(선택+후필터)
  - `infer_attrs` 미등재 분기 → `vocab_select` 우선, 실패 시 기존 `gemma_expand`+`_match_to_graph` **fallback**(이것도 graph_kw만).
- **검증**: `스파이시 마라` → 매콤·강렬·자극적·얼큰함… (**파이 소멸**), `부드러움` 정상 포함, 전 쿼리 100% 그래프 멤버.
- **특성**: DeepSeek/Ollama 공통(`_llm` 경유). 알려진 트렌드는 config 조회 우선 → LLM 미사용. 비용은 *새 키워드* 경로만, 어휘 prefix는 캐시.

## 2. 핵심 결론·인사이트

1. **bypass(손해)는 "100% 멤버십 충족"이나 "손해"는 오역** — 실제는 −0.3~0.8%p ≈ 0인 **중복(대체재)**. 쫄깃함이 레일에 있어 떡·면이 잉여. substitution(`findings/2026-06-21_조합-포화-substitution.md`)의 재현.
2. **레일 순서 = 빈도가 아니라 인과 Δprob 리프트 순서** (combo_grow). support가 단조롭지 않은 게 증거.
3. **LLM 자유생성+문자열매칭은 의미 무지** — `스파이시→파이`. 어휘 제약 선택이 정답(멤버십 ∧ 의미). 단순 string 임계로는 `로제소스→로제`(정상)와 구분 불가.
4. **배포는 정적 불가** — `/combo`는 torch GNN 추론이라 **상시 컨테이너 필수**(Vercel 서버리스 불가). LLM만 API로 빼면 GPU 불필요 → 가벼운 CPU 호스트.
5. **로컬 수정 → 링크 반영 = 푸시가 곧 배포**(자동 아님). 모델 갱신 시 `sync_serving_assets.py` 추가 실행.

## 4. 주의사항 (gotchas)

- **`.gitignore` 경로무관 패턴**: `data/`(이름 data인 디렉터리 어디든)·`*.pt`(어디든) → 배포 번들은 폴더명 `data` 회피 + `.pt`만 negation. 새 산출물 추가 시 `git check-ignore`로 추적 확인.
- **`keyword_basket_comp_edges.parquet` 필수**(v2): `_inject_basket_comp`이 부재 시 FileNotFoundError. 번들·sync 스크립트에 포함됨.
- **`.env`는 git 미추적**(시크릿) — 로컬은 `.env`, 배포는 Railway Variables. `_load_local_env`는 `setdefault`라 **이미 설정된 env(Railway)가 우선**.
- **콘솔 cp949**: 헤드리스 한글/이모지 print는 `PYTHONIOENCODING=utf-8` 필요.
- **vocab_select 비용**: 어휘 1,923개 프롬프트. 알려진 키워드는 config 조회로 LLM 자체를 건너뜀(비용 0). 새 키워드만 과금.
- **Railway 슬립 티어**: 비활성 후 첫 요청 콜드스타트(모델 로드 수 초). 상시는 유료.
- **api.py warmup**: `serve.llm_warmup()` — deepseek면 no-op(불필요한 Ollama 콜드로드 방지).
