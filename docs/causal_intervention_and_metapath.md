# 🧬 인과적 개입 머신(Δprob) 및 HIN 메타패스 확장 기반 키워드 관계 분석 명세서

본 문서는 7-Eleven NPD AI 프레임워크가 단순히 상관관계(Purity)에 의존하여 발생할 수 있는 오분류(FP/FN)를 방어하고, **인과적 성공 기여도(Δprob)**를 측정하기 위해 HIN 상에서 **메타패스를 어떻게 확장하고 키워드 간의 인과적 관계를 파악하는지** 기술적 메커니즘을 명세합니다.

---

## 🗺️ 1. 데이터 및 방법론 설계 배경

* **상관관계(Purity)의 한계**: 성공 제품에 우연히 같이 붙어 등장하는 키워드는 높은 Purity를 기록하지만, 실제 성공을 유발(Causal Driving)하지는 않습니다. (예: `띠부씰`은 높은 Purity를 가지나 성공의 주원인은 캐릭터 파트너의 IP 후광임)
* **인과적 개입 머신(Δprob)의 해법**: 가상 올스타 노드(Virtual Concept Node)를 생성하여, 해당 키워드가 **존재하지 않는 가상의 제품에 이 키워드를 강제로 삽입(개입, Intervention)**했을 때 전체 HIN 전파를 거쳐 최종 도출되는 성공 확률의 상승치($\Delta prob = prob_{post} - prob_{pre}$)를 직접 실측합니다.

## 🎯 2. 키워드 분류 판별기준 (killer / mine / 매개 + 지표 정의)

§1의 개입 머신(Δprob)을 기반으로, 전 키워드를 **3개 출력 유형**(killer·mine·매개)으로 추리는 구체적 임계와 그때 쓰는 지표의 의미를 먼저 정의합니다. 이 분류가 산출하는 점수(purity·Score·WoE 등)가 §3 메타패스 전파를 거쳐 어떻게 계산되는지는 이어지는 §3에서 상술합니다. 이 기준은 `src/eval/md/classify.py`의 `classify_keywords_live(eng)`에 그대로 코드화되어 **모델 로드 시 1회** 라이브 재계산·캐시됩니다(데이터/모델 스왑 시 자동 추종). hub는 출력 유형이 아니라 **분류용 내부 게이트·기준선**입니다.

### A. 출력 유형 = 3개 (hub는 내부용)

| 유형 | MD 의미 | 판별 축 |
|---|---|---|
| **killer** | "넣어라" — 성공 유발 | 성공 특이성 + 인과 유발 |
| **mine** | "피해라" — 실패 신호 | 실패 특이성 + 인과 악재 |
| **매개** | "아무 데나 넣으면 +" — 보편 강화제 | 보편 리프트 (특이성과 직교) |
| ~~hub~~ | (출력 X) | **내부 게이트·기준선**: killer를 일반어로부터 가르고, purity 해석의 baseline |

> hub는 서빙 태그로 내보내지 않는다(=neutral 취급). 역할은 ① 간식·디저트 같은 범용어가 killer로 새는 것 차단 ② "killer=백본보다 성공특이"의 기준선.

### B. 공통 지표 (단일 추론 1회 + 라벨 — 재추론 없음)

각 지표가 **무엇을 측정하는지**가 핵심입니다. 관찰 지표는 어텐션 카운트만으로 싸게 계산됩니다.

| 지표 | 정의 | 의미 (왜 보는가) |
|---|---|---|
| `base_rate` | `n_succ/(n_succ+n_fail) = 0.238` | 전체 성공률. purity 해석의 기준선(이보다 높아야 성공특이) |
| `Score_succ(k)` | `Σ_4경로 Σ_{성공제품 p} att(p,k)` | 성공 제품들이 k에 보낸 어텐션 총량 (has_kw·via_ip·ipip·trend 4경로) |
| `Score_fail(k)` | `Σ_4경로 Σ_{실패제품 p} att(p,k)` | 실패 제품들이 k에 보낸 어텐션 총량 |
| `purity(k)` | `Score_succ / (Score_succ + Score_fail)` | **성공 특이성**. base 0.238 대비 높으면 성공에 쏠린 키워드 |
| `Hub_Score(k)` | `Σ_경로 Σ_p att(p,k)·Mass[p]`, `Mass=z(sim_kw deg)+z(sim_ip deg)` | 연결 질량 가중 어텐션 = **무색무취 백본**일수록 큼 |
| `att_lift(k)` | `(Score_succ/n_succ)/(Score_fail/n_fail)` | 모델 관점 성공/실패 비. **희소성 편향 있음**(rare 키워드 과대) |
| `WoE(k)` | `ln( (supp_s/n_succ)/(supp_f/n_fail) )` | Weight of Evidence = **통계 관점** 성공 증거. 희소성 편향 없어 att_lift 교차검증용 |
| `빈도(k)` | 직접 has_kw 제품 수 | **실제 증거량**. 우회경로 supp가 아니라 직접 보유 수(거품 게이트) |
| `단독성공률(k)` | `mean( y[k 보유 제품] )` | raw·model-free 성공률 (base 강도 가늠) |
| `단독_wilson(k)` | 단독성공률의 Wilson 95% 하한 | **소표본 페널티**(공주 1.0→0.21) |

### C. 검증 지표 (개입 = 재추론, 모델 로드 시 1회 라이브 — `classify.py`가 배치 계산)

| 지표 | 정의 | 의미 |
|---|---|---|
| `Δprob(k)` | `평균_캐리어[ score(캐리어+k) − score(캐리어) ]` | **인과 유발**. 그래프에 k를 추가 후 재forward한 성공확률 순증 |
| `Δprob_cond(k\|IP)` | `score([k]\|IP) − score([]\|IP)` | IP 조건부 유발 (공룡류처럼 IP 후광에 묻힌 키워드 구제) |
| `delta_pos(k)` | `Δprob>0 인 캐리어 비율` | **보편성**. 1.0이면 어느 제품에 붙여도 +(매개 판별 핵심) |

> **왜 재추론?** Δprob는 *반사실*("k를 넣으면?")이라 단일 추론엔 그 상태가 없다. 관찰(purity·단독성공률)은 *교란*(공룡=IP 후광)을 못 가르고, 개입(캐리어 고정+k만 토글)만 순수 기여를 분리한다. GNN 비선형이라 분석적 계산 불가.

### D. 유형별 판별기준 (임계)

**killer — 성공 특이 + 인과 유발**
```
[분류·관찰]  빈도≥3 ∧ supp_s≥3 ∧ purity≥0.50 ∧ Score_succ≥Q75 ∧ WoE>0 ∧ supp_f>0
[검증·인과]  Δprob>0   (Δ≤0 → 조건부(Δcond>0) 또는 가짜 강등)
```
- **판정 tier** (노이즈밴드 ±0.01): 확실(Δ>+0.01) / 불명확(±0.01) / 조건부(Δ≤0 ∧ Δcond>0) / 가짜(Δ<−0.01 ∧ Δcond≤0)
- 근거 축: purity↑(성공특이) · WoE>0(통계신호) · **Δprob>0(유발)** · 단독성공률↑(강한 base)

**mine — 실패 특이 + 인과 악재 (killer의 대칭)**
```
[분류·관찰]  빈도≥3 ∧ supp_f≥3 ∧ purity≤0.15 ∧ Score_fail≥Q75 ∧ WoE<0 ∧ supp_s>0
[검증·인과]  Δprob<0   (Δ≥0 → 통계만, 의심)
```
- 잡히는 종류: 건강·기능성(다이어트·운동·칼로리) / 주류 니치(와인·사케·하이볼) / 무거운 식사·국물(찌개·짜장·육수) / 레드오션 향·맛(마라·향신료·산미) / 무드 추상어(행복·휴식)

**매개 — 보편 증폭 (killer/mine과 직교)**
```
[분류·관찰]  빈도≥5 ∧ supp_all≥10 ∧ supp_all<400(메가허브 제외) ∧ 단독성공률<0.45 ∧ ~killer ∧ ~mine
[검증·인과]  delta_pos≥0.7(거의 전캐리어 +) ∧ Δprob_mean>0.04
```
- 잡히는 종류: 포맷(즉석·삼각) / 맛질감(짭조름함·감칠맛·쫄깃함) / 기능(저당·당충전) / 콜라보(허쉬·쿠앤크) / 굿즈(캐릭터·키링)

**hub — 내부 게이트 (출력 X)**
```
빈도≥3 ∧ supp_all≥3 ∧ |purity−0.238|<0.15 ∧ Hub_Score≥Q80 ∧ att_lift<1.5 ∧ |WoE|<0.5 ∧ ~killer ∧ ~mine
```
- 역할: killer false-positive 차단(간식·디저트) + purity baseline. **서빙 태그 아님(neutral 출력)**.

### E. 빈도 보정 (소표본 거품 제거)

소표본은 극단값을 쉽게 얻어 유리하다: 공주·뷰티(직접 제품 1개)가 단독성공률 1.0·purity 1.0.

| 보정 | 방법 | 효과 |
|---|---|---|
| **빈도 floor** | killer/mine `빈도≥3`, 매개 `빈도≥5` | n=1~2 명백한 거품 제거 (공주·뷰티·행복) |
| **Wilson 하한** | `단독_wilson` 컬럼 | 소표본 자동 페널티 (공주 1.0→0.21, 하와이 0.83→0.55) |

- **빈도** = 직접 has_kw 제품 수. `supp`(우회 IP·트렌드 경로 포함)는 직접 1개여도 3 이상이 될 수 있어 부족 → 직접 빈도로 게이트.
- n=3(공룡)은 빈도로 안 자르고 **인과(Δprob 조건부)**가 판단 — 빈도+인과 역할 분담.

### F. 3층 필터 요약

```
1. WoE 분류        (관찰, 단일추론)   ← purity·WoE·Score·att_lift
2. + 빈도 보정     (관찰, 단일추론)   ← 빈도 floor·Wilson (소표본 거품)
3. + Δprob 검증    (개입, 재추론)     ← 유발(killer)·악재(mine)·보편(매개)
```
- 1·2 = 싸다(엣지 카운트). 3 = 비싸다(재추론) — **모델 로드 시 1회 라이브**, 후보(killer/mine) Δprob은 공유 헤드룸 표본 1배치로 축약(`classify._batch_delta`).
- **공주(n=1)** = 소표본 → 2가 잡음. **공룡(Δ≤0)** = 교란 승객 → 3이 잡음. 둘 다 필요.
- **killer < mine 은 구조적**: base 0.238 = 제품 76%가 실패 → "실패하는 길"이 "성공하는 길"보다 많다. killer=좁은 처방 shortlist / mine=포괄 블랙리스트로 역할이 달라 비대칭이 적절.

## 🔗 3. HIN 메타패스 확장 및 전파 메커니즘

§2의 분류 점수(Score_succ·purity 등)는 모델이 키워드 노드의 신호를 제품 노드로 전파한 어텐션의 집계입니다. 그 전파가 HIN 상에서 어떻게 일어나는지를 명세합니다. HIN(Heterogeneous Information Network) 상에서 예측 모델은 제품과 속성(키워드/IP) 간의 다중홉 전파를 수행합니다. 2홉($L=2$) 전파 하에서 단일 키워드 개입이 어떻게 예측 확률을 변화시키는지에 대한 수학적·구조적 흐름은 다음과 같습니다.

### A. 인접행렬 차원 확장 및 간접 엣지 유도
제품(Product) 노드가 속성(IP/Keyword)의 영향력을 직접적으로 받기 위해, $L=2$ 홉의 전파 경로를 사전 계산한 간접 인접행렬로 축약하여 그래프에 직접 주입합니다.
1. **제품-IP-키워드 경로 ($A_{has\_kw\_via\_ip}$)**:
   $$A_{has\_kw\_via\_ip} = A_{PI} \times A_{IK}$$
   제품($P$)이 특정 IP($I$)를 채택하고, 그 IP가 특정 트렌드 키워드($K$)와 연결되어 있을 때의 간접적인 속성 흐름을 2홉 경로로 계산하여 1홉짜리 직접 엣지로 투사합니다.
2. **제품-IP-IP-키워드 경로 ($A_{has\_kw\_ipip}$)**:
   $$A_{has\_kw\_ipip} = A_{PI} \times A_{II} \times A_{IK}$$
   단절되었던 IP-IP 브릿지 관계($A_{II}$, `ip_ip_edges_final.parquet`)를 복원하여, 제품이 채택한 IP가 다른 IP와 협업/유사 관계를 맺고 최종 키워드로 수렴하는 3홉 경로의 연산을 사전 연산하여 주입합니다.

### B. 메시지 패싱 및 어텐션 전파
1-Layer HGT(Heterogeneous Graph Transformer) 구조 하에서, 개입된 특정 키워드 노드 $k$의 초기 임베딩 $H_k^{(0)}$는 위의 유도된 간접 엣지 통로들을 타고 제품 노드 $p$로 메시지를 전달합니다.
* 제품 노드의 임베딩 업데이트 식:
  $$H_p^{(1)} = \sum_{r \in \mathcal{R}} \alpha_r \cdot \text{Attention}_r(p, k) \cdot (W_r H_k^{(0)})$$
  여기서 $\alpha_r$은 DiffMG를 통해 학습된 관계 가중치입니다. `co_offline`과 같은 장바구니 누수 엣지가 제거됨에 따라, 모델은 오직 $A_{has\_kw\_via\_ip}$ 와 $A_{has\_kw\_ipip}$ 와 같은 **콘텐츠 중심의 전파 경로에 가중치($\alpha_r$)를 적극 분화시켜 임베딩을 구성**하게 됩니다.

## ⚖️ 4. 1홉 이후 키워드 간 관계 파악 및 인과 진단

단일 키워드의 1홉 메시지 패싱이 완료된 후, 여러 키워드가 하나의 가상 제품 노드에 동시에 개입할 때의 상호작용은 단순 선형 결합이 아닙니다. GNN의 비선형 활성화 함수 및 어텐션 정규화로 인해 발생하는 **두 가지 핵심 키워드 관계 구조**를 진단합니다.

### A. Modifier vs Base 구조 (캐리어 base 강도와 증폭기 모델)
인과적 기여도 분석 도구인 `keyword_context_breakdown`을 통해 분석한 결과, 특정 기획 키워드는 그 자체로 충분조건이 아닌 **일정 수준의 성공 확률을 상향시키는 증폭기(Modifier)**의 역할을 수행함이 증명되었습니다.

* **인과적 기여도(contrib) 정의**: 제품 $p$에서 키워드 $k$를 배제했을 때의 확률 하락폭
  $$contrib(p, k) = prob(p) - prob(p \setminus \{k\})$$

* **고창(지역 브랜딩) 키워드 실증 사례**:
  * 빈츠, 카스타드와 같이 기존 중분류의 힘(Carrier Base 강도)이 이미 강한 제품($prob \ge 0.9$)에서는 고창을 제거해도 성공 예측치에 영향이 거의 없습니다 ($contrib \le 0.016$). 브랜드 파워가 성공을 주도하고 고창은 묻어가는 구조입니다.
  * 마가렛트, 찰떡파이와 같이 베이스 강도가 중간인 제품군에서는 고창이 **$+0.30$ 안팎의 성공률 리프트(증폭)**를 발생시켜 성공 임계값(THR)을 돌파하게 만듭니다.
  * 소프트캔디 카테고리에 속한 말랑카우의 경우, 카테고리 자체의 베이스 강도가 너무 약해 고창이 동일하게 $+0.30$에 가까운 리프트를 주었음에도 불구하고 최종 확률이 $0.335$에 머물러 성공 임계값 돌파에 실패합니다.
* **MD 처방 함의**: `고창` 등의 킬러 지역명은 **"충분조건이 아닌 증폭기"**이므로, 기본 카테고리 체급(Base 강도)이 우수한 제품군(예: 비스킷류)과 결합할 때 시너지가 나며, 약체 카테고리에서는 단독으로 제품을 살려낼 수 없습니다.

### B. 대체재 및 수확체감 구조 (Saturation & Substitution)
여러 개의 강한 키워드를 하나의 상품에 연속적으로 추가하는 시뮬레이션(`combo.combo_beam`)을 진행할 때, 특정 임계점 이상에서는 **성공 기여도가 급격히 포화(Saturation)**되는 현상이 나타납니다.

* **마라 앵커 조합의 단계별 Marginal 리프트 실측**:
  * 마라 앵커 단독 개입 시: 성공 확률 **$+0.7711$ 폭증** (강력한 단일 드라이버)
  * 마라 + 짭조름함 개입 시: 추가 기여도 **$+0.0387$** (미미한 보강)
  * 마라 + 짭조름함 + 콜라보 개입 시: 추가 기여도 **$+0.0001$** (**완전 포화**)
* **상호작용 해석 (대체재 효과)**:
  * 이미 성공 확률이 고점에 도달한 강한 키워드 조합에서는 추가되는 다른 강한 키워드들이 서로를 강화하는 보완재(Superadditive)가 아니라, **동일한 어텐션 풀을 나눠 갖는 대체재(Substitution, 1+1 < 2)**로 작동하여 시너지 로그-오즈 가중치가 음수($\approx -10$)로 떨어집니다.
  * 진짜 비즈니스 시너지는 약한 키워드 간의 결합에서만 극소량 존재할 뿐이며, 강한 키워드 영역에서는 단일 앵커 키워드에 적절한 보조 키워드를 매핑하는 것이 정답입니다.
* **MD 처방 함의**: 상품 기획 시 무조건 강한 콘셉트를 여러 개 덧씌우는(예: 마라 흑임자 약과) 기획은 수확체감으로 인해 마케팅 오버헤드만 발생시킬 뿐 모델 상의 성공 확률을 올리지 못합니다. **"확실한 단일 앵커 + 방향이 맞는 보조 키워드"** 구조의 단출한 조합이 최적입니다.

## 💻 5. 대시보드 및 MD 처방 운영 연동

본 인과 추론 엔진은 실무 대시보드 및 API 연동을 통해 실시간으로 MD 기획을 지원합니다.

1. **`seed_partners` (인과 파트너 테이블) 활용**:
   * 대시보드 상에서 MD가 메인 앵커 키워드(Seed)를 선택하면, 개입 머신 `Δprob`을 백그라운드에서 실시간 연산하여 해당 앵커의 성공 확률 헤드룸을 가장 잘 채워주는 보조 키워드 목록(보강 $\Delta > 0$ / 방해 $\Delta < 0$)을 매핑하여 대시보드 화면에 시각적으로 tag(색상 뱃지) 처리합니다.
2. **라이브 키워드 분류 (A안 — `src/eval/md/classify.py`)**:
   * 정적 `keyword_final.csv` 대신 `classify_keywords_live(eng)`가 **모델 로드 시 1회** 관찰 게이트(build_ledger+WoE)→인과 tier(Δprob)→매개 룰을 돌려 killer/mine/매개/hub 태그를 산출·캐시한다. **데이터/모델을 갈아끼우면 마커가 자동 재계산**된다(요청당이 아니라 로드당). 가짜 killer(Δ≤0)는 자동 강등(neutral).
   * **대시보드 2층**: ① 한 키워드 클릭 → **전역 분류**(이 태그, 절대 Δprob 기준) / ② 두 키워드 클릭 → **국소 시너지**(맥락 margin). combo 경로(torch)가 노드에 `gtag`를 부착(`combo_serve.build_seed`).
3. **IP 추천 = 인과 margin (어텐션 아님)**:
   * "잘 어울리는 IP(콜라보 후보)"는 어텐션 가중(선 굵기)이 아니라 **`pair_synergy_ip`의 인과 margin(seed 기준)** 내림차순으로 랭킹한다. 이로써 **추천 랭킹과 클릭 시 궁합 패널이 동일 수치**가 되어, "어텐션으론 강하게 엮이나 인과 순증은 ≈0(중복)"인 IP(예: 초코×키키블룸 −0.6%p)가 추천에서 자동 탈락하고, 진짜 +Δ(예: 초코×포켓몬스터 +1.1%p)만 남는다.

## ⚖️ 6. 전역 사전(EDA) vs 국소 문장(대시보드)의 2층 정합성 논리

학습된 단일 예측 및 개입 엔진을 기반으로, 본 프레임워크는 전역적 분류(EDA)와 국소적 전개(대시보드)라는 서로 다른 두 해상도의 층위를 상보적으로 연동하여 일관성 있는 정보를 서빙합니다.

### A. 전역 vs 국소 층위 구조 비교
전역 분류가 개별 키워드의 정적 사전을 구축하는 것이라면, 국소 대시보드는 이 사전을 재료 삼아 맥락에 맞춰 동적으로 문장을 구성하는 역할을 합니다.

| 구분 | EDA / keyword_finalization (전역 사전) | 대시보드 (국소 문장) |
|---|---|---|
| **분석 범위** | 전역 (네트워크 전체 노드 대상) | 국소 (선택한 특정 시드 및 조합에 한정) |
| **핵심 질문** | "이 키워드 자체가 독립적으로 무엇인가?" | "이 조합 맥락에서 이 키워드가 어떻게 작동하나?" |
| **산출물** | killer/mine/매개 **라이브 태그**(`classify.py`, A안) | pair synergy 및 combo의 동적 결합 전개 |
| **결정 시점** | **모델 로드 시 1회 라이브 재계산·캐싱**(데이터 스왑마다 자동) | 사용자 클릭 마다 실시간/선계산 API 추론 |
| **동작 엔진** | `MDEngine` (단일 추론 + 개입 머신) | `MDEngine` (동일 엔진 상에서 국소 슬라이싱) |

### B. 정적 태그 vs 동적 맥락의 일관성과 2층 정보 제공
키워드가 전역적으로는 `killer` (성공 특이)이더라도, 이미 성공 확률이 포화된 강한 조합(강+강 대체재 구조)에 추가되는 맥락에서는 `잠식(Saturation)`으로 판정될 수 있습니다. 본 프레임워크는 대시보드 상에서 두 정보를 동시에 제공함으로써 논리적 정합성을 유지합니다.
* **대시보드 노드 표기 (1층, 한 키워드 클릭)**: 전역 기준 **"노드 태그(killer/mine/매개/hub) 뱃지 + 설명"** (`dashboard.html`의 `GTAG_INFO`/`_gtagRow` — 2026-06-24 실제 렌더링됨). 예: "이 키워드는 전체에서 성공을 유발하는 경향(prior)입니다."
* **대시보드 엣지 표기 (2층, 두 키워드 클릭)**: 조합 시점의 **"국소 pair synergy/잠식 라벨"** (예: "이 강한 조합 맥락에선 대체재로 작동해 추가 리프트가 잠식됩니다").
* **연관 ≠ 인과 주의**: 추천(IP·파트너)은 **어텐션(연관)이 아니라 인과 margin**으로 랭킹해야 1층·2층이 어긋나지 않는다. 어텐션 추천 + 인과 클릭은 "Purity 높은데 Δ≈0"(§1 띠부씰)을 재현하는 함정 — 그래서 IP 추천도 `pair_synergy_ip` margin으로 통일했다(§5-3).
* **결론**: 두 정보는 상충 오류가 아니라 **전역(절대 Δprob) ↔ 국소(맥락 margin)의 의도된 2층**이며, 같은 개입 머신·단일 노이즈 플로어(±0.01) 위에서 일관된다.

### C. 대시보드 렌더링에 미치는 영향 분석 (Hub ➡️ Neutral 및 매개 태그)
1. **Hub ➡️ Neutral 변경**: 
   * 대시보드 네트워크 시각화는 **노드 타입**(`속성=초록`, `제품=빨강`, `IP=주황`)을 기준으로 색칠됩니다.
   * `hub` 태그를 `neutral`로 강등하거나 변경하는 것은 노드의 속성 라벨(뱃지)만 지워질 뿐, 전체 네트워크 렌더링 구조와 색상에는 전혀 영향을 주지 않고 백본 노드로서 정상 작동합니다.
2. **매개 등 전역 태그 뱃지 (구현 완료)**:
   * combo 경로(`combo_serve.build_seed`)가 `classify_keywords_live`의 태그를 키워드 노드 `gtag`로 부착하고, 프론트(`dashboard.html` `GTAG_INFO`/`_gtagBadge`/`_gtagRow`)가 killer/mine/매개/hub 뱃지+설명을 렌더한다. 노드 타입색(속성=초록·제품=빨강·IP=주황)은 유지하고 분류는 뱃지로 얹어 렌더 스키마를 깨지 않는다.
3. **임계 정합성 보증 (코드 정합 완료)**:
   * 국소 synergy 임계($2 \times \text{SE}$)와 전역 개입 $\Delta$ 임계($0.01$)가 노이즈 플로어 상 동일 기준선으로 통일된다. **2026-06-24 코드 정합**: 대시보드 pair 패널 임계 0.001→**0.01**, `classify.py` `NOISE=0.01` — 문서·코드 일치.
