# 🛒🩷 키워드 채널 적합도 분석 — 방법론 및 결과 (인스타 vs POS)

> **목적**: 각 속성 키워드가 **온라인 바이럴(인스타)**과 **오프라인 매출(POS)** 중 어느 채널에서 성공을 *유발*하는지 인과적으로 판별하여, MD가 서브네트워크에서 뽑은 키워드를 **"마케팅 카피용"** vs **"제품 내실용"** 으로 배분할 수 있게 한다.
> **모델**: `v2_sweepA` (현 서빙) · **엔진**: `src/eval/md/engine.py` (`score_concept` 개입 머신) · **노트북**: `experiments/notebooks/channel_fit_eda.ipynb`
> **방법론 근거**: [`causal_intervention_and_metapath.md`](causal_intervention_and_metapath.md) §2 (관찰 게이트 → 인과 Δ 검증)

---

## 1. 무엇을 잡으려 했나 (문제 정의)

키워드가 어느 채널에 어울리는지를 **상관(등장 빈도)** 이 아니라 **인과(성공 유발)** 로 가리는 것이 목표다.
- **인스타형** = 그 키워드가 **온라인 바이럴 성공을 유발** → 초기 마케팅 카피로 활용
- **POS형** = 그 키워드가 **오프라인 매출 성공을 유발** → 제품 스펙·내실로 활용
- **범용** = 양쪽 다 유발 → 어디든 무난

## 2. 방법론 (처음부터 끝까지)

### 2-1. 채널 배타 분할 — "POS 성공"과 "인스타 성공"을 깨끗이 가른다
성공 제품(`성공여부=='성공'`)을 `성공_소스` 기준으로 **상호 배타** 분할. 둘 다 성공한 제품(POS+인스타)은 채널 판별에 노이즈라 **제외**.

| 채널 성공군 | 정의 (`성공_소스`) | 제품 수 |
|---|---|---|
| **POS 단독성공** | `POS` | **614** |
| **인스타 단독성공** | `인스타` / `CU_인스타` / `GS25_인스타` | **265** |
| (제외) 둘 다 성공 | `POS+인스타` | 318 |

### 2-2. 관찰 게이트 — 채널별 증거량 (커버리지)
killer/mine과 동일하게 **총 빈도 ≥ 3** 키워드(1,100개)를 base로 삼고, 채널별 보유 제품 수로 게이트:
- **POS 게이트**: POS 단독성공 제품에서 **≥ 3회 등장** (POS는 표본 풍부)
- **인스타 게이트**: 인스타 단독성공 제품에서 **≥ 1회 등장** (인스타는 표본 얇아 1로 완화)

> 인스타 단독성공이 265개뿐이라 구조적으로 표본이 얇음 → 인스타 보유 1~2개는 **저신뢰(⚠)** 플래그.

### 2-3. 인과 Δ (ablation) — "빼봤을 때 성공확률이 떨어지나"
키워드를 *보유한* 채널 성공작에서 그 키워드를 **빼보고**(`score_concept`로 가상 재구성), 성공확률 하락폭을 채널별로 평균:

```
contrib(p,k) = prob(제품 p) − prob(p에서 k 제거)
Δ_pos(k)   = mean_{k 보유 POS성공작}  contrib
Δ_insta(k) = mean_{k 보유 인스타성공작} contrib
```
- 대시보드 `combo`·`classify`와 **동일 프리미티브** → 노이즈 플로어 **±0.01** 통일.
- 같은 제품의 full/ablate를 한 청크에 넣어 차분 상쇄(정확도 확보).

### 2-4. ★ 부호 게이트 + margin — 분류 (핵심 교정)
**처음엔 `margin = Δ_insta − Δ_pos` 만으로 분류했으나, 이것이 결함이었다.** margin은 "어느 쪽으로 *덜* 기우나"만 재기 때문에, **둘 다 성공을 깎는데(Δ<0) 인스타가 덜 깎이는** 키워드를 "인스타형"으로 오분류했다 (margin-only 인스타형의 **72%가 Δ_insta ≤ 0** = 실제론 바이럴을 깎는 키워드).

→ **Δ 부호 게이트를 추가**: 그 채널에서 **Δ > +0.01 (진짜 유발)** 일 때만 그 채널형으로 인정.

| 태그 | 조건 |
|---|---|
| 🩷 **인스타형** | `Δ_insta > +0.01` ∧ (POS도 유발이면 margin이 인스타 쪽) |
| 🟢 **POS형** | `Δ_pos > +0.01` ∧ (인스타도 유발이면 margin이 POS 쪽) |
| 🟡 **범용** | 양쪽 다 `Δ > +0.01` ∧ `|margin| ≤ 0.01` |
| ⚠ 주의(드래그) | `Δ < −0.01` (빼는 게 나음 → 추천 금지) |
| 효과미미 / 채널미정 | `Δ ≈ 0` / 증거 없음 |

## 3. 결과 요약

base 1,100개 키워드 중 부호 게이트 적용 후:

| 태그 | 수 | 비율 | 해석 |
|---|---|---|---|
| 🩷 인스타형 | **86** | 7.8% | 바이럴 유발 (카피용) |
| 🟢 POS형 | **57** | 5.2% | 매출 유발 (제품용) |
| 🟡 범용 | **15** | 1.4% | 양쪽 유발 |
| **= 진짜 채널 드라이버** | **158** | **14.4%** | |
| ⚠ 주의(드래그) | 280 | 25.5% | Δ<0, 빼는 게 나음 |
| 효과미미 | 65 | 5.9% | Δ≈0 |
| 채널미정 | 597 | 54.3% | 채널 성공 증거 없음 |

> **핵심**: margin-only가 뽑은 503개 "채널 판정" 중 **70%가 허수(드래그)**였고, 부호 게이트 후 **신뢰 가능한 드라이버는 158개**. 채널 라벨은 killer/mine/매개와 **대체로 직교한 새 정보**(인스타형의 다수가 전역 neutral).

## 7. 해석 — 채널색이 직관과 일치

- **인스타형**은 *보는 즐거움·트렌드·이색성* (디저트·해외컨셉·굿즈·지역·시즌). 바이럴은 "사진과 화제성"으로 터진다는 도메인 직관과 일치.
- **POS형**은 *먹는 본질·기능·내실* (식감·감칠맛·건강기능·간편식·검증된 제과 브랜드). 매출은 "맛·실속·반복구매"로 난다는 직관과 일치.
- **범용**은 *보편 식감/단맛* (촉촉·달콤·부드러움) — 채널 불문 기본기.

---

## 8. 신뢰도·한계

- **인스타 표본 구조적 부족**: 인스타 단독성공 265개(95%가 CU/GS25)뿐 → 인스타형 86개 중 **상당수가 보유 1~2개(⚠)**. 단단한 인스타형은 보유 ≥3인 것(하와이·시즌·케이크·크림·어묵·맥주·에일 등). ⚠는 방향성 참고용.
- **POS형은 표본 충분**(보유 ≥3 강제) → 신뢰도 높음.
- **드래그 280개 / 미정 597개**는 채널 추천 대상이 아님 — 대시보드에서 채널 안내를 띄우지 않는다.
- **success-conditioned**: Δ는 "성공작에서 그 키워드가 떠받친 정도"라, 신제품에 얹었을 때의 채널 효과에 대한 **인과 근사**다.

## 9. 대시보드 적용 결론

1. **채널 판별 로직은 유효하고 라이브 가능** — `combo` 서브네트(0.06s) + 채널 부착 ≈0. gtag(killer/mine)와 동일하게 **로드 1회 산출 → 서브네트 노드에 부착**.
2. **반드시 부호 게이트 적용** — margin-only는 드래그를 카피로 오추천하므로 폐기.
3. **노드 색은 기존 타입색 유지** — 속성 키워드=초록(`#16A34A`) / IP=주황(`#F59E0B`). **채널은 노드색이 아님.** 범례도 속성/IP만.
4. **채널은 노드 하나 클릭 시 세부 패널 뱃지로만** 표시: 🟢 POS형 / 🩷 인스타형 / 🟡 범용 + 설명. 인스타형 보유 1~2개면 ⚠ 저신뢰.
5. **사용 흐름**: MD가 서브네트에서 5개를 뽑으면 — 인스타형 → 카피 문구, POS형 → 제품 스펙, 범용 → 베이스로 자유 배치.

> 연동 방식: `classify_channel_live`(로드 1회 캐시) + `combo_serve.build_seed`에서 노드 `ctag` 부착 = gtag와 동일 패턴. single-click = 채널 라벨 / two-click = 기존 synergy (불변).

## 10. 대시보드 계산 명세 (어떤 수치 → 어떤 값)

대시보드는 **단일 추론 캐시 1회**에서 시작해 4단계로 키워드별 채널 태그를 만든다. 아래는 각 수치의 **정의와 의미**다.

### 10-1. 입력 수치 (단일 추론 캐시 — 로드 시 1회)

| 수치 | 정의 | 의미 (왜 쓰나) |
|---|---|---|
| `prob[p]` | 제품 p의 모델 성공확률 | Δ(빼봤을 때 변화)의 기준선 |
| `y[p]` | 성공여부 (1/0) | 성공작만 채널 근거로 씀 |
| `succ_src[p]` | 성공_소스 (POS / 인스타 / …) | 성공을 **어느 채널이 견인했나** → 배타 분할 키 |
| `product_keywords(p)` | p가 가진 키워드 집합 (has_kw) | k 보유 여부 + 가상 제품 재구성 |

### 10-2. 단계별 산출 수치

```
[1] 채널 마스크 (배타)
    pos_idx   = (y==1) ∧ (succ_src=='POS')                    # POS 단독성공 614
    insta_idx = (y==1) ∧ (succ_src ∈ {인스타,CU_인스타,GS25_인스타})  # 인스타 단독성공 265

[2] 채널 보유수 (게이트용)
    pos_n(k)   = |{p∈pos_idx   : k∈product_keywords(p)}|
    insta_n(k) = |{p∈insta_idx : k∈product_keywords(p)}|

[3] 인과 기여도 Δ (개입 머신, score_concept ablation)
    contrib(p,k) = score_concept(키워드들) − score_concept(키워드들 \ {k})
    Δ_pos(k)   = mean_{p∈pos_idx,   k보유} contrib(p,k)
    Δ_insta(k) = mean_{p∈insta_idx, k보유} contrib(p,k)

[4] 분류 (노이즈 플로어 ±0.01 — 대시보드 synergy와 동일 기준선)
    margin(k) = Δ_insta(k) − Δ_pos(k)

    pos_drive = (pos_n≥3)   ∧ (Δ_pos > +0.01)      # 부호 게이트(유발 양수)
    ins_drive = (insta_n≥1) ∧ (Δ_insta > +0.01)

    ctag(k) =
      둘 다 drive → margin>+0.01: 🩷인스타형 / <−0.01: 🟢POS형 / else: 🟡범용
      ins_drive만 → 🩷인스타형
      pos_drive만 → 🟢POS형
      Δ<−0.01     → ⚠주의(드래그)      # 채널 추천 안 함
      그 외        → 효과미미 / 채널미정

    저신뢰(k) = insta_n < 3              # 인스타 표본 1~2개
```

### 10-3. ★ 각 수치가 의미하는 것

| 수치 | 의미 | 판정에서의 역할 |
|---|---|---|
| `pos_n(k)` / `insta_n(k)` | 그 채널 성공작 중 k를 **실제로 단** 제품 수 = **증거량** | 게이트(POS≥3, insta≥1). 적으면 신뢰 불가 |
| `Δ_pos(k)` | POS 성공작에서 k를 빼면 성공확률이 떨어지는 폭 = **k가 매출 성공을 유발한 정도** | `>+0.01` 이어야 "POS 진짜 드라이버" |
| `Δ_insta(k)` | 인스타 성공작에서 동일 = **k가 바이럴 성공을 유발한 정도** | `>+0.01` 이어야 "인스타 진짜 드라이버" |
| `margin(k)` | `Δ_insta − Δ_pos` = **두 채널 중 어디서 더 세게 유발하나** (쏠림 방향·크기) | 양쪽 다 유발일 때 채널 *기울기* 결정 |
| `±0.01` (노이즈 플로어) | 우리 finding의 2·SE 스케일 = **이보다 작으면 0과 구분 불가** | Δ·margin 모두 이 밴드로 끊음 (synergy·전역분류와 통일) |
| `저신뢰` | insta 표본 1~2개 = 방향성 참고용 | 뱃지 흐리게, 처방 신중 |

> **부호 게이트의 의미 (핵심)**: `Δ>+0.01` 조건이 없으면 margin만으로 "덜 해로운 쪽"이 채널형으로 뽑혀 **드래그 키워드를 카피로 오추천**한다(§2-4). 그래서 "**그 채널에서 실제로 성공을 끌어올리나(Δ 양수)**"를 먼저 통과해야만 채널형을 부여한다.

### 10-4. 최종적으로 노드에 붙는 값

키워드당 **`(Δ_pos, Δ_insta, pos_n, insta_n)` 4수치**가 원천이고, 여기서 파생된 **`ctag`(단일 채널 태그) + `margin` + `저신뢰`** 가 서브네트 노드에 부착된다.

| UI 동작 | 사용 값 | 표시 |
|---|---|---|
| 노드 색 | (타입) | 속성=초록 / IP=주황 — 기존 유지, 채널과 무관 |
| 클릭 세부 패널 채널 뱃지 | `ctag` | 🟢POS형 / 🩷인스타형 / 🟡범용 + 설명 (insta 1~2개면 ⚠ 저신뢰) |
| 클릭 패널 | `ctag` + `Δ_pos`·`Δ_insta`(%p) + `pos_n`·`insta_n` + `저신뢰` | "인스타 성공 +X%p 유발 → 카피용" |
| MD 5개 배분 | 각 키워드 `ctag` | 인스타형→카피 / POS형→제품 / 범용→자유 |

> **연산 위치**: [1]~[4]는 gtag와 동일하게 **로드 시 1회 배치**(`score_concept_batch`)로 계산·캐시(`eng._channel_tags`). `combo_serve.build_seed`는 캐시된 `ctag`를 **dict 조회로 부착**(추가비용 ≈0) → 서브네트는 기존처럼 라이브. two-click synergy 로직은 불변.
