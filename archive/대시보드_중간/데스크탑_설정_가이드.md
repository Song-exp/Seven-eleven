# 데스크탑 Gemma API 서버 설정 가이드

> **작성일:** 2026-04-29  
> **대상:** 시연용 데스크탑 담당자  
> **목적:** 외부 네트워크 환경에서 Gemma LLM을 API 서버로 운영하기 위한 설정

---

## 개요

노트북(FastAPI 백엔드)이 LLM 추론 요청을 **데스크탑의 Gemma API 서버**에 위임한다.  
데스크탑은 Ollama를 통해 `gemma4` 모델을 실행하고, ngrok으로 외부에 노출한다.

```
[Vercel 대시보드]
      ↕ fetch
[노트북] server.py (:8000)
      ↕ POST /generate  +  Authorization: Bearer MAPISODE_SECRET_2026
[데스크탑] server.py (:8000)  ─── ngrok ───→ 외부
      ↕
[데스크탑] Ollama → gemma4
```

---

## ✅ 완료된 단계 (Phase 1~3)

### Phase 1 — Ollama + Gemma4 구동 ✅

- Ollama 설치 완료
- `ollama run gemma4` 실행으로 모델 다운로드 및 동작 확인
- Ollama 백그라운드 실행 중 → `http://localhost:11434` 대기 상태

### Phase 2 — FastAPI 중간 서버 구축 ✅

아래 코드로 `server.py`를 작성하고 포트 `8000`에서 실행:

```python
from fastapi import FastAPI, HTTPException, Header
from pydantic import BaseModel
import requests

app = FastAPI()

MY_SECRET_KEY = "MAPISODE_SECRET_2026"

class ChatRequest(BaseModel):
    prompt: str

@app.post("/generate")
async def generate_text(request: ChatRequest, authorization: str = Header(None)):
    if authorization != f"Bearer {MY_SECRET_KEY}":
        raise HTTPException(status_code=401, detail="Unauthorized")

    ollama_url = "http://localhost:11434/api/generate"
    payload = {
        "model": "gemma4",
        "prompt": request.prompt,
        "stream": False
    }

    try:
        response = requests.post(ollama_url, json=payload, timeout=120)  # ← timeout 권장
        response.raise_for_status()
        return {"response": response.json().get("response", "")}
    except Exception as e:
        raise HTTPException(status_code=500, detail=f"Ollama 에러: {str(e)}")
```

```powershell
# 서버 실행 (터미널 1)
uvicorn server:app --host 0.0.0.0 --port 8000
```

> ⚠️ **주의:** 위 코드에서 `requests.post()` 호출 시 `timeout=120` 추가를 권장합니다.  
> 미설정 시 Ollama가 느릴 때 무한 대기 상태가 될 수 있습니다.

### Phase 3 — ngrok 터널 ✅

```powershell
# 터미널 2 (서버는 그대로 유지)
ngrok http 8000
```

실행 후 `Forwarding` 항목의 `https://` URL 확인:

```
Forwarding  https://abcd-12-34-56-78.ngrok-free.app -> http://localhost:8000
```

## 🔲 남은 단계 — Phase 4: 노트북 연결

데스크탑에서 발급된 ngrok URL을 노트북 담당자에게 전달한다.

### 노트북 `.env` 수정 (3줄)

```ini
# 변경 전
LLM_MODE=local
# REMOTE_LLM_URL=https://xxxx.ngrok-free.app
# REMOTE_LLM_KEY=DEV_KEY

# 변경 후
LLM_MODE=remote
REMOTE_LLM_URL=https://abcd-12-34-56-78.ngrok-free.app   ← 데스크탑 ngrok URL
REMOTE_LLM_KEY=MAPISODE_SECRET_2026                       ← Phase 2의 MY_SECRET_KEY와 동일
```

### 노트북 FastAPI 서버 재시작

```powershell
# 기존 uvicorn Ctrl+C 종료 후
uvicorn server:app --port 8000
```

### 연결 확인

```powershell
# llm_mode: remote 확인
Invoke-RestMethod http://localhost:8000/api/health
```

정상 응답:
```json
{
  "status": "ok",
  "llm_mode": "remote",
  "endpoint": "https://abcd-12-34-56-78.ngrok-free.app"
}
```

## 주의사항

| 상황 | 대응 |
|---|---|
| ngrok 재시작 시 URL 변경 | 노트북 `.env` `REMOTE_LLM_URL` 재설정 + 서버 재시작 |
| Ollama 응답 없음 | Ollama 앱 재실행 후 `ollama run gemma4` |
| ngrok 무료 세션 8시간 만료 | 재실행 → 새 URL 노트북에 재전달 |
| 첫 Gemma 추론이 느림 (30~60초) | 정상, 이후 응답 빠름 |
| 노트북 API 호출 타임아웃 | `gemma_server.py`의 `TIMEOUT_SEC` 기본값 120초 |

## 엔드포인트 참조 (데스크탑 서버)

| Method | Endpoint | 설명 |
|---|---|---|
| GET | `/` | 서버 상태 확인 |
| POST | `/generate` | 프롬프트 → Gemma 추론 결과 반환 |

```powershell
# /generate 직접 테스트 (데스크탑 로컬)
$body = @{ prompt = "안녕하세요. 한 문장으로 답해주세요." } | ConvertTo-Json -Compress
$headers = @{ Authorization = "Bearer MAPISODE_SECRET_2026" }
Invoke-RestMethod -Uri http://localhost:8000/generate -Method POST -Body $body -ContentType "application/json" -Headers $headers
```
